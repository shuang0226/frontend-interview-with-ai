# H5 居中手机画布设计

## 目标

将 H5 端统一呈现为以小程序窄屏样式为基准的手机画布，修复宽屏浏览器中优惠中心被横向拉伸、遮罩铺满整个窗口的问题。

## 已确认的体验

- 设计宽度为 390px。
- 桌面宽屏采用方案 A：浅灰浏览器背景中的纯净居中内容区；不显示设备边框或投影。
- 视口宽度不大于 390px 时，应用继续占满屏幕，保持现有手机浏览体验。
- 改动只作用于 H5；微信小程序和其他编译目标的组件结构、尺寸和交互不变。

## 方案

在全局样式中增加仅由 H5 DOM 命中的根画布规则：宽屏时将应用根节点限制为 390px 宽、最小高度为可见视口高度并水平居中；页面外部使用浅灰背景。窄屏媒体条件下恢复根节点的 100% 宽度。

优惠中心和地址编辑器当前使用固定定位，因此它们不受普通根节点宽度限制。为这两类已有浮层增加与画布一致的 H5 宽度和水平定位规则：宽屏时覆盖中央 390px，窄屏时覆盖整个手机视口。优惠中心的底部弹层、遮罩、滚动区、按钮和飞券动画仍在同一个固定定位范围内计算，不修改其业务状态与动画时序。

## 代码边界

- 修改 `src/app.scss`：承载 H5 根画布和宽屏背景规则。
- 修改 `src/components/coupon-center/index.scss`：让优惠中心遮罩在宽屏时约束到画布内。
- 修改 `src/components/address-editor/index.scss`：让现有地址编辑浮层遵循同一画布边界。
- 不修改优惠券、地址的数据和领取/编辑交互 TypeScript 代码。

## 验收与验证

1. 在宽于 390px 的 H5 浏览器中，页面内容始终为居中的 390px 区域，外部为浅灰背景。
2. 打开优惠中心后，灰色遮罩和底部面板都只出现在该 390px 区域；标题、标签、按钮不再横向拉伸。
3. 在 390px 及以下宽度，地址页和优惠中心仍全宽显示且可滚动、领取、关闭。
4. H5 构建、微信小程序构建、TypeScript 类型检查和已有单元测试均通过。

## 错误与兼容性

此方案仅调整 CSS 布局，不引入新的运行时状态或网络依赖。`env(safe-area-inset-bottom)` 等现有安全区计算继续保留；没有安全区信息的桌面浏览器回退为零。浮层在边界宽度处使用同一组媒体条件，避免遮罩与面板使用不同宽度。
