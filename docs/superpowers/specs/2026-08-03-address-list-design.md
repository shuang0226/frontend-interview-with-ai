# 地址列表跨端页面设计

## 目标

使用 Taro 3 与 React 实现一套可运行的地址列表页面，视觉参照提供的截图，并在 H5、微信小程序、支付宝小程序、抖音小程序与 React Native 中尽量保持一致。

列表项支持选择默认地址，以及编辑地址、联系人、手机号和任意数量的标签。初始演示数据包含短地址、超长地址、前置标签和后置标签四种场景。

## 范围

包含：

- 地址列表、当前默认地址的单选状态与整行点击切换。
- 编辑入口与编辑弹层，保存后即时写回列表。
- 标签新增、删除与文本编辑。
- 地址两行截断规则。
- 前置标签与后置标签的稳定布局规则。

不包含持久化接口、地址新增/删除、真实地图定位或服务端校验。

## 技术与组件边界

- 使用 Taro 3、React 和 TypeScript，页面由 Taro 基础组件 `View`、`Text`、`Input`、`Button` 组成。
- `AddressList` 仅拥有地址数组与当前选中项的状态，并向子组件传递稳定的事件回调。
- `AddressItem` 只负责单条地址的可访问渲染、选择和打开编辑器；以地址 `id` 作为 key。
- `AddressEditor` 使用受控字段编辑单条数据，保存时返回一个完整、已校验的地址对象；取消不修改列表。
- `TagList` 管理单条地址编辑草稿中的可变数量标签，使用生成的稳定标签 id，不使用数组下标作为 React key。

## 两行与标签排版

每个列表项的主文案区域最多显示两行，内容只有一行时按一行行高自然收高，不预留第二行空白；溢出内容截断。地址与标签作为独立的行内块，避免依赖富文本或 Canvas 测量。

- 前置标签：位于地址开头，多个标签按自然宽度排列；标签占用首行可用空间，地址从剩余位置开始流动。空间不足时地址在第二行继续，整体不超过两行。
- 后置标签：地址与标签放在同一个两行容器中。后置标签通过 `max-width: 50%`（等价 Taro 样式）限制自身宽度，超长标签本身省略；地址优先占用内容宽度，标签只能作为第二行末尾内容出现。
- 跨端降级：H5 使用标准多行截断能力；小程序/RN 使用“最大两行高度”而非固定两行高度，并配合溢出裁切，保证一行内容不留空白、两行内容不出现第三行。由于各端字形度量不同，截断文字的精确字符数可以不同，但行数、标签最大宽度和视觉层级保持一致。

## 交互与校验

- 点击地址项（编辑图标及其区域除外）将其设为默认地址；选中标记立即变化。
- 点击编辑图标打开弹层，预填当前值。
- 地址、联系人、手机号均为必填；手机号以数字和常用分隔符为允许字符。标签可为空数组，单个标签为空时不能保存。
- 点击保存会校验并替换该 id 的数据，关闭弹层；点击取消或遮罩关闭则丢弃草稿。
- 图标和选择项使用可访问标签，输入框具有关联名称；不会通过颜色作为唯一状态提示。

## 验证

- TypeScript 严格模式检查。
- 单元测试覆盖：选择地址、编辑并保存、取消编辑、标签增删、超长后置标签的宽度限制标记。
- 以 H5 为主要手工验收面，使用演示数据确认：地址最多两行、长标签不会超过容器一半、编辑结果实时反映到对应列表项。

## 验收标准

1. 页面结构、颜色层级、分隔线、选择状态和编辑入口与参考图接近。
2. 所有地址无论长度如何均不会显示第三行。
3. 后置标签显示在第二行末尾时，视觉宽度不超过主文案区域的 50%。
4. 标签内容和数量可变，编辑后立即反映。
5. H5、微信、支付宝、抖音与 RN 均只使用 Taro 支持的基础组件和样式，不依赖 DOM 专属 API。
