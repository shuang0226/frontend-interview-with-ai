# 地址列表实施计划

> 依赖已确认的设计：[地址列表跨端页面设计](../specs/2026-08-03-address-list-design.md)。

## 1. 初始化可运行的 Taro 3 + React + TypeScript 工程

创建 Taro 3 React 模板及严格 TypeScript 配置，并保留 H5、微信、支付宝、抖音和 RN 的构建脚本。设置页面入口为地址列表页面，加入跨端全局重置样式。验证：`tsc --noEmit` 与 H5 构建均成功。

## 2. 定义领域模型与演示数据

新增 `src/types/address.ts` 和 `src/data/addresses.ts`：定义地址 id、联系人、手机号、标签、标签位置（`leading`/`trailing`）和默认状态；填入与截图对应的长短文案用例。验证：数据中 id 唯一，覆盖一行、两行、超长前置/后置标签场景。

## 3. 实现跨端两行排版组件

新增 `src/components/address-text/`：

- `AddressText.tsx` 依据标签位置选择前置或后置布局；不借助 DOM 测量。
- `TagPill.tsx` 渲染可变文本标签并对标签自身作单行省略。
- `index.scss` 以基础 flex、行高、`max-height` 与 `overflow: hidden` 实现“最多两行”；内容一行时自然收高。
- 后置标签额外使用 `max-width: 50%`，并使用底部对齐结构确保其是第二行的结尾内容。
- 为平台差异提供仅用 Taro 认可的样式降级，不引入 `window`、`document` 或 CSS 选择器依赖。

验证：在 H5 中逐项检查没有第三行、单行不留空白、后置标签最大宽度不超过主内容区一半。

## 4. 实现地址列表、选择与编辑入口

新增 `src/components/address-item/AddressItem.tsx`、样式文件及 `src/pages/index/index.tsx`：

- 使用地址 id 作为稳定 key。
- 以 `useState` 维护地址数组和默认地址 id，点击非编辑区域设为默认地址。
- 右侧编辑入口阻止事件冒泡，只打开该地址的编辑弹层。
- 使用 `View`、`Text` 和 `Button`（或兼容图标文字）实现选择标记、分隔线、联系人行与编辑入口；添加无障碍文本。

验证：切换后只有一个默认项，编辑入口不会改变默认项。

## 5. 实现受控编辑弹层与标签编辑

新增 `src/components/address-editor/AddressEditor.tsx`、样式文件和纯校验函数：

- 弹层的地址、联系人、手机号和标签均为受控输入；首次打开从选中项复制为草稿。
- 支持新增、修改、删除任意标签，并为每个标签生成稳定 id。
- 保存时验证必填字段、手机号字符与空标签；成功后用完整新对象替换原 id 的地址，取消则清除草稿。
- 使用能在 Taro 目标端工作的模态层实现，避免 H5 专属 `prompt`/原生对话框。

验证：编辑并保存后对应列表即时变化；取消不改变数据；空地址、空联系人、非法手机号和空标签有可见提示。

## 6. 补齐错误边界、测试与多端检查

- 添加轻量错误边界，避免单个渲染错误让页面空白。
- 使用 React Testing Library/Vitest（依模板支持情况选择兼容适配）覆盖选中、保存、取消、标签增删和后置标签限制。
- 运行 TypeScript 检查、测试和 H5 构建；若环境可用，运行微信、支付宝、抖音和 RN 的编译检查。
- 在 README 中写明安装、H5 启动及各目标端构建命令与限制说明。

## 实施顺序与检查点

先完成 1–2 并验证工程可运行，再完成 3 并手工确认关键排版，随后完成 4–5 的交互，最后执行 6 的自动与构建验证。每一阶段失败均先修复再进入下一阶段。
